$ ss -ltn | grep ":80 " || echo "port 80 free on the host"
port 80 free on the host

=========== Step 1: pull Apache ===========
$ docker pull httpd:2.4
Digest: sha256:979c38c2228d28c2edfd45c6e27dcee1c7b4a101a5526721ae8ece454e89e99e
Status: Image is up to date for httpd:2.4
docker.io/library/httpd:2.4

=========== Step 2: run it on the HOST network ===========
$ docker run -d --name apache-host --network host httpd:2.4
ce420d948d2a636341cb3556d9457eb4d62db5d70614b17540312273df25d6c0

$ docker ps --filter name=apache-host --format "table {{.Names}}	{{.Image}}	{{.Status}}	{{.Ports}}"
NAMES         IMAGE       STATUS         PORTS
apache-host   httpd:2.4   Up 3 seconds   
  ^ the PORTS column is EMPTY - there is no mapping, because there is no separate namespace to map from

=========== Step 3: access it directly on host port 80 ===========

$ ss -ltnp | grep ":80 "
LISTEN 0      511                *:80               *:*                                    
  ^ httpd is listening on the HOST's port 80 itself

=========== Step 4: proof the namespace really is shared ===========
$ docker exec apache-host hostname   # same hostname as the host
Pottu-Lappy
$ hostname                          # -> Pottu-Lappy

$ docker inspect apache-host --format "{{.HostConfig.NetworkMode}}"
host
$ docker inspect apache-host --format "IP={{.NetworkSettings.IPAddress}} (empty: no dedicated IP)"

template parsing error: template: :1:22: executing "" at <.NetworkSettings.IPAddress>: map has no entry for key "IPAddress"

=========== Step 5: -p is IGNORED with --network host ===========
$ docker run -d --name apache-mapped --network host -p 8085:80 httpd:2.4
